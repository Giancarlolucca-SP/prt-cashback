# S10-US07: Seguranca, Auditoria e Administracao Tecnica

## Epic
Configuracoes, Permissoes, Perfis e Administracao do Sistema

## Objetivo
Definir regras de seguranca, auditoria, sessoes, logs, retencao, backups e administracao tecnica para proteger dados da loja, clientes, documentos, financeiro, integracoes e operacoes sensiveis.

## Historia de Usuario
**Como** Dono/Gestor,
**quero** controlar seguranca, auditoria e administracao tecnica do sistema,
**para** garantir rastreabilidade, protecao de dados, continuidade operacional e controle sobre acessos criticos.

## Escopo do MVP
A historia cobre:

- Login e politica de sessoes.
- Bloqueio de usuario inativo.
- Controle de tentativas de acesso.
- Logs imutaveis de auditoria.
- Logs tecnicos de integracoes e automacoes.
- Retencao de dados e arquivos.
- Backup e restauracao operacional.
- Politicas LGPD aplicadas a dados pessoais e documentos.
- Administracao tecnica por Dono/Gestor e perfis autorizados.
- Exportacao controlada de dados quando permitido.

## Login e Sessoes
- Usuario deve acessar com login individual.
- Nao deve existir usuario compartilhado para operacao diaria.
- Usuario inativado deve perder acesso imediatamente.
- Quando possivel, inativacao deve derrubar sessoes ativas.
- Sistema deve registrar ultimo acesso do usuario.
- Sistema deve permitir redefinicao de senha por fluxo seguro.
- Dono/Gestor pode forcar troca de senha de usuario.
- Sessao deve expirar por inatividade conforme parametro configuravel.

## Politicas de Acesso
- Permissoes definidas na S10-US01 devem ser aplicadas no backend.
- Tentativas de acesso a areas bloqueadas devem ser negadas.
- Dados financeiros, DRE, margem, NF financeira, documentos pessoais, logs e integracoes devem respeitar perfil e escopo.
- Vendedor nao acessa logs sensiveis, logs de anuncios, prestadores financeiros, DRE, margem ou custos fora do permitido.
- SDR, Avaliador e Responsavel por Servicos/Estetica acessam apenas o necessario para suas funcoes.
- Dono/Gestor possui acesso completo.
- Administrativo pode acessar rotinas tecnicas/operacionais somente se autorizado.

## Auditoria Imutavel
Devem gerar log de auditoria:

- Login e logout quando aplicavel.
- Falha de login.
- Bloqueio de acesso por permissao.
- Criacao, edicao, inativacao e reativacao de usuario.
- Alteracao de permissao/perfil.
- Alteracao de configuracoes da loja.
- Alteracao de impostos, comissoes, categorias, templates, canais e automacoes.
- Criacao, edicao, exclusao/inativacao e reativacao de registros sensiveis.
- Upload, exclusao e visualizacao de documentos sensiveis quando aplicavel.
- Exportacao de dados.
- Envio automatico/manual por WhatsApp/e-mail.
- Acionamento de IA/automacao.
- Resultado de consultas externas quando registradas no sistema.
- Alteracoes em dados financeiros, conciliacao, custos, pagamentos e comissoes.

## Campos Minimos do Log
Cada log deve registrar, quando disponivel:

- Usuario responsavel.
- Perfil do usuario no momento da acao.
- Data e hora.
- Modulo.
- Tipo de acao.
- Registro afetado.
- Valor anterior e novo valor quando aplicavel.
- Origem: usuario, automacao, IA, integracao ou sistema.
- IP/dispositivo quando disponivel.
- Resultado: sucesso, erro, bloqueado ou pendente.

## Retencao e LGPD Operacional
- Dados pessoais e documentos devem ser armazenados apenas quando houver finalidade operacional, legal, contratual ou legitima necessidade da loja.
- Documentos de venda, compra, financeiro e transferencia devem seguir retencao definida pela loja/contador/juridico.
- O sistema deve permitir localizar dados de um cliente quando houver solicitacao LGPD.
- Exclusao definitiva de dado sensivel deve ser restrita a Dono/Gestor ou processo autorizado.
- Quando um dado nao puder ser apagado por obrigacao legal/contratual, o sistema deve permitir registrar motivo de retencao.
- Logs de auditoria nao devem ser editaveis pelo usuario.

## Arquivos e Documentos
- Uploads devem ficar vinculados ao modulo, card, cliente, veiculo, venda, compra, OS ou processo correspondente.
- Sistema deve registrar quem anexou, quando anexou e tipo/classificacao do arquivo.
- Exclusao de anexo deve gerar log.
- Anexos sensiveis devem respeitar permissao por perfil.
- Visualizacao/download de documentos sensiveis pode gerar log conforme configuracao.

## Backups e Continuidade
- Deve existir politica de backup do banco e arquivos anexados.
- Dono/Gestor deve conseguir visualizar status basico do ultimo backup ou receber alerta de falha.
- Restauracao deve ser processo tecnico controlado, nao uma acao livre de usuarios comuns.
- Falha critica de backup, integracao ou automacao deve gerar alerta para Dono/Gestor e/ou perfil autorizado.

## Administracao Tecnica
Dono/Gestor ou perfil tecnico autorizado pode:

- Ver status de integracoes principais.
- Ver status de canais WhatsApp/e-mail.
- Ver fila/erros de automacoes.
- Ver eventos de sincronizacao com marketplaces, IA, despachante, financeira e outros servicos.
- Solicitar reprocessamento de tarefa quando for seguro.
- Inativar integracao/regra em caso de erro.
- Exportar logs tecnicos quando necessario para suporte.

## Permissoes
- Dono/Gestor acessa seguranca, auditoria, administracao tecnica e logs completos.
- Administrativo pode visualizar logs e status tecnicos operacionais se autorizado.
- Administrador pode receber permissoes tecnicas conforme decisao do Dono/Gestor.
- Vendedor, SDR, Avaliador e Responsavel por Servicos/Estetica nao acessam logs sensiveis ou administracao tecnica.
- Usuarios comuns visualizam apenas informacoes operacionais do seu escopo.

## Criterios de Aceite
- Dado que usuario inativo tenta acessar, quando informar credenciais, entao o sistema deve negar acesso.
- Dado que usuario sem permissao tenta acessar modulo sensivel, quando solicitar, entao o sistema deve bloquear e registrar log quando aplicavel.
- Dado que Dono/Gestor altera permissao, configuracao, canal, imposto, comissao, categoria, template ou regra, quando salvar, entao deve gerar log de auditoria.
- Dado que documento sensivel e anexado ou excluido, quando a acao ocorrer, entao deve registrar usuario, data/hora e vinculo do arquivo.
- Dado que automacao, IA ou integracao executa acao, quando finalizar, entao deve registrar origem, resultado e erro quando houver.
- Dado que houver falha critica de canal, backup, integracao ou automacao, quando detectada, entao deve gerar alerta para responsavel configurado.
- Dado que Dono/Gestor consulta auditoria, quando filtrar por usuario, modulo, periodo ou acao, entao deve visualizar registros correspondentes.
- Dado que usuario comum tenta editar log, quando solicitar, entao sistema deve bloquear.
- Dado que a loja precisa localizar dados de cliente, quando buscar pelo cadastro, entao sistema deve apresentar os vinculos principais para suporte a LGPD.

## Fora de Escopo
- SIEM corporativo avancado.
- SSO empresarial no MVP.
- Criptografia customizada fora das boas praticas da stack.
- Portal externo de suporte tecnico.
- Automacao de restauracao de backup por usuario final.

## Observacoes Tecnicas
- Logs de auditoria devem ser append-only.
- Permissoes devem ser verificadas no backend e nao apenas na interface.
- Arquivos devem usar armazenamento com controle de acesso.
- Preferir trilha de auditoria separada dos dados editaveis.
- Backup deve considerar banco de dados e arquivos anexados.
- Eventos tecnicos devem preservar correlacao com card/processo quando existir.
